## Why

FlowGuard currently contains the pieces needed for a living software model, but several runtime boundaries still let a declared plan, stale receipt, compact projection, or temporary artifact be mistaken for current executable evidence. This change closes the task-map, bounded hierarchical execution, evidence, freshness, and finite-completion gaps identified in the 2026-09-04 audit so an AI can locate an affected surface, execute only its declared closure, and finish without an unbounded freshness loop.

## What Changes

- Add a task-local projection to the existing affected-blueprint route, resolving changed paths to current intent, code coordinates, typed impact paths, contracts, validation owners, and explicit gaps without creating a second authority.
- Classify working evidence, staging, caches, and release/current-authority inputs separately; preserve working bytes while excluding non-authoritative artifacts from source identity and publication.
- Fix compact finite exploration to visit every initial state and require native completion counts and exact oracle results.
- Enforce one canonical semantic identity for completion plans, independent of output paths, and provide strict same-parent reuse with zero producer launches.
- Tighten native case/result, JUnit, model-miss, canonical-relation, affected-closure, and five-level hierarchical evidence contracts so missing, foreign, skipped, malformed, or aggregate-only evidence blocks rather than passes.
- Add a persistent bounded completion cycle and a public canonical readiness envelope; retire the duplicated readiness path and prevent retries or output-directory changes from resetting the cycle.
- Contract only the explicitly identified duplicate branches/owners and document the distinction between structural model readiness, dynamic evidence, architecture audit, and release readiness.
- Reduce recurring map and route cost without weakening semantic ownership: read-only maps must be zero-producer, affected work must traverse one bounded closure, and the fifteen public routes must share frozen context and lazy references.
- Add a production gate for partitioned finite composition so a local or pairwise denominator cannot be presented as a full-equivalent claim without an independently bound coupling denominator and parent evidence.
- Require the self-blueprint owner inventory to bind every checked-in validation script used by self-maintenance to one exact model owner before formal qualification; a missing binding is a model-closure failure, not a reason to weaken the check.
- Gate the internal AgentWorkflowRehearsal mode by typed workflow-risk facts: ordinary small, single-owner, read-only, targeted-test, or multi-tool work records `not_triggered` and does not load the rehearsal protocol.
- Treat a merged source revision that changes the governed implementation or route
  contract as a new reviewed completion scope.  The new scope must record the
  source revision, retain the exhausted predecessor as historical evidence, and
  use one fresh finite completion cycle; changing only an output directory,
  cache, or disposition label must never reset the cycle.

## Capabilities

### New Capabilities

- `runtime-evidence-task-map`: Resolve a bounded, evidence-aware task map and currentness envelope from existing model and ownership authorities.
- `finite-hierarchical-execution`: Verify real multi-level model/test composition with finite cells, typed joins, progress, and child receipts.

### Modified Capabilities

- `project-layout-contract`: Permit controlled working/staging artifacts while excluding them from authority and release identity.
- `flowguard-model-authority-currentness`: Make accepted snapshots, source identity, and working deltas explicit and non-fallback.
- `flowguard-model-regression-orchestration`: Require exact native case/oracle bindings, real completion counts, and affected execution semantics.
- `flowguard-evidence-receipts`: Enforce strict raw-artifact, owner, subject, and protocol verification for reuse.
- `flowguard-self-maintenance-mesh`: Add persistent finite completion cycles, canonical readiness, and zero-producer reuse.
- `post-runtime-model-miss-review`: Separate prepared from closed miss reviews and require finite evidence-backed closure.
