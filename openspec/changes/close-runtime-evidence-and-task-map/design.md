## Context

The existing FlowGuard package already owns model authority, blueprint readers, native model/test runners, evidence receipts, completion epochs, and distribution checks. The audit found that these authorities are not consistently joined: the CLI can eagerly load unrelated objects, compact exploration can miss initial states, output-only paths can alter semantic identity, and several consumers accept markers or aggregate summaries in place of exact evidence. The implementation must preserve the existing authorities and dirty worktree while adding only the missing joins.

## Goals / Non-Goals

**Goals:**

- Make one existing affected-blueprint route produce a bounded task-local map with provenance and gaps.
- Preserve working/staging bytes while making authority and release projections explicit.
- Enforce exact native case/oracle evidence, real finite hierarchical execution, and honest miss closure.
- Make completion identity and readiness canonical, persistent, bounded, and reusable without producer loops.
- Keep light, affected, and full execution semantics distinct and remove only named duplicate owners/branches.

**Non-Goals:**

- No second map/index authority, no broad repository rewrite, and no cleanup by deletion or relocation.
- No automatic changes to ResearchGuard, PhysicsGuard, WorldGuard, FlowPilot, remote Git, tags, or releases.
- No promotion of structural or model-policy evidence to implementation behavior without native evidence.

## Decisions

1. **Reuse existing authorities.** The task map reads current model authority, implementation inventory, behavior commitments, bindings, and content-addressed receipts. It never infers semantic ownership from AST calls or caller-provided owner lists.
2. **Separate semantic and execution identity.** A single normalization routine removes only registered output-path arguments from semantic command identity. Inputs, oracle, cases, toolchain, environment, and dependencies remain identity inputs; execution paths remain record metadata.
3. **Use strict typed result envelopes.** Native runners emit exact source case IDs, dimensions, oracle results, raw-artifact fingerprints, and input identities. Aggregates name their children. Missing, malformed, skipped, foreign, or duplicate evidence is a blocker.
4. **Bound composition by declared properties.** The five-level fixture executes finite leaf cells and joins. Pairwise combinations are not global coverage unless the three-way property is explicitly declared. Parent verification is a receipt-consumption operation, not a dataclass-construction shortcut.
5. **Persist one completion cycle.** Existing epoch storage/lease mechanisms record the initial attempt and one typed repair. Readiness is a canonical envelope produced by the same planner used by full execution; reuse-only reads a verified terminal parent and performs no writes or launches.
6. **Classify, do not delete, temporary artifacts.** Path safety is checked before exclusion. Work/staging and generated bytecode remain physically present but are excluded from source authority and release projections; unknown governed source and reparse-point hazards still block.
7. **Integrate incrementally.** Parallel edits are limited to the three isolated routes in the Action List. Shared CLI/protocol work is integrated by the primary owner after targeted tests, followed by one frozen final validation.
8. **Make route cost an execution invariant.** The public route count remains fifteen semantic owners, but route selection loads only the selected route and its first protocol layer. A read-only map consumes one invocation-local source/receipt observation and starts no producer, lease, run directory, authority write, or installation write. An affected request reuses the same observation and traverses one typed closure; it does not rebuild a second topology search.
9. **Require a declared coupling denominator for partitioned composition.** `allow_partitioned_product` may produce a scoped local result, but a full-equivalent result additionally requires an independently current boundary source, topology/head identity, required interaction groups, relation materializations, interface/refinement binding, executed cells, and parent consumption. Caller-provided booleans or a candidate plan copied into its own verification context are never sufficient.
10. **Freeze profile admission before execution.** `light`, `affected`, and `full` are selected from typed operation facts before any producer or lease. A specialist route never upgrades itself; conflicting explicit profile/operation facts are blocked. Author qualification remains a separate internal assurance owner and is not run by ordinary light map reads.
11. **Close self-blueprint ownership before qualification.** Every checked-in validation script that participates in the self-maintenance mesh, including the author-skill assurance runner, must have one exact model owner in the authoritative software blueprint. The self-maintenance review fails closed when that mapping is absent; it never treats a filename, route label, or aggregate parent as an implicit owner.

12. **Keep the coupling denominator pointer-free.** The accepted boundary
    contract is a v2 content-addressed semantic artifact. Its fingerprint is
    derived only from the boundary source, finite axes/groups, relation
    materializations, and a pointer-free model/relation topology projection.
    Snapshot, accepted-revision, head, activation, and output identities are
    binding context supplied by the verified authority loader; they are not
    serialized into the contract identity. Snapshot owner references and
    revision candidate hashes remain intact, so authority still verifies the
    binding without creating a contract→snapshot→revision→contract cycle.

13. **Keep AgentWorkflowRehearsal conditional and internal.** The
    DevelopmentProcessFlow simulator admits its `agent_workflow` mode only for
    an explicit rehearsal request, cross-owner handoff/shared write,
    post-validation-invalidating write, agent/route workflow change, or
    multiple independent owners with irreversible side effects. A list of
    skills/tools, an external-effect label, a non-trivial label, or entry
    through the public process owner alone does not justify rehearsal. The
    internal protocol has no public alias and is not loaded for `not_triggered`
    work, which keeps ordinary prompt and evidence cost bounded.

14. **Make source revisions explicit completion scopes.** A completion cycle is
    finite for one reviewed objective and one frozen source observation.  When a
    real merge changes a governed source or route contract after that cycle has
    consumed its initial and repair attempts, the owner must update the reviewed
    objective scope and record the new source revision before opening a fresh
    cycle.  Historical aborted ledgers remain immutable evidence; output paths,
    cache locations, receipt disposition labels, and retry wording cannot buy a
    new attempt.

## Risks / Trade-offs

- [Risk] Existing dirty files can overlap the repair. → Inspect exact diffs and preserve unrelated work; stop a batch on a baseline conflict instead of overwriting it.
- [Risk] Historical receipts use older schemas. → Keep them as historical evidence and require current protocol/identity for normal reuse; do not add a compatibility success path.
- [Risk] Strict native binding exposes real missing cases. → Report the exact binding or boundary ID as blocked; never weaken the oracle or substitute a convenient test.
- [Risk] Windows symlink/reparse permissions may be unavailable. → Preserve a typed blocked/not_run result and do not alter system security policy.
- [Risk] The final full run is time- and attempt-bounded. → Freeze all source/tool identities and run targeted checks first; consume at most the remaining repair attempt.

## Migration Plan

1. Create and validate this change; record a baseline without starting the historical producer.
2. Apply layout, task-map, compact-explorer, semantic-identity, evidence, affected-closure, hierarchy, miss, JUnit, and completion-cycle changes in the Action List order.
3. Run affected targeted checks and strict OpenSpec validation; update only genuinely completed task items.
4. Compile and project the formal skill source to the author shadow and installed consumer roots, then perform one frozen readiness/full/reuse sequence if all gates pass.
5. Leave work/evidence/staging artifacts in place, publish no remote release, and report remaining external OpenSpec tasks separately.
