## Why

FlowGuard already records layered model, owner, and evidence relationships, but a normal consumer can still be blocked by unrelated whole-system currentness and a first bootstrap can report success before the normal current reader can consume it. Pointer/activation metadata and release-tree observations can also reopen functional work, so self-upgrades repeatedly spend time without reaching a stable terminal state. This change makes the smallest useful map usable first and makes one upgrade close under a finite, explicit work budget.

## What Changes

- Add a real two-model consumer lifecycle: first adoption produces a current-readable authority, basic navigation works without deep projection, and affected updates retain unrelated model navigation.
- Separate selected functional input identity from authority pointer/activation binding identity; pointer-last commit performs finite integrity checks without rerunning validated functional producers.
- Separate local functional completion from release-tree/install qualification; reports, checkboxes, receipts, and temporary work evidence never self-invalidate functional producers.
- Give one completion work item a stable identity and bounded initial/repair attempts; timeouts terminate descendants and do not silently launch retries.
- Make patch review maps consume an explicit source change manifest and distinguish planned changes from test-time drift; remove the empty-delta all-model authorization path.
- Route workflow rehearsal only from the existing risk-admission facts and document light/affected/full boundaries consistently.
- Make the same finite convergence and release-consumer rules apply to ordinary external software, with arbitrary finite hierarchy depth rather than a fixed parent/child/grandchild shape.
- **BREAKING**: current completion and authority records use the direct current schema; no compatibility reader, alternate pointer, fallback authority, or second receipt store is added.

## Capabilities

### New Capabilities

- `consumer-current-closure`: bounded first adoption, local map navigation, affected closure, and pointer-last functional completion for a small consumer.
- `finite-completion-work`: stable work identity, bounded attempts, timeout cleanup, and terminal non-reopening behavior.

### Modified Capabilities

- `authoritative-model-system`: first adoption must result in a current-readable accepted revision and pointer binding must be distinct from selected model content.
- `development-process-flow`: local functional claims and release claims have separate scopes and ordinary work does not require author full validation.
- `model-test-alignment`: affected model, connection, code, and test evidence is selected from exact typed dependencies rather than all-model fallback.

## Impact

Affected Python modules include the model authority/revision store, existing-model preflight, affected blueprint CLI, validation ownership/completion epoch/readiness, process supervision, patch-review helpers, and their existing tests. The author-maintained skill source and OpenSpec change artifacts also need direct-current contract/projection refresh. Consumer installation remains a clean projection and does not gain a SkillGuard runtime dependency.
