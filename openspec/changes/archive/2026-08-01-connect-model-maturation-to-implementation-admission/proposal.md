## Why

FlowGuard already owns current-model lookup, open-angle review, task-local model maturation, development-process freshness, risk evidence, and final closure, but those owners are not joined into one enforceable pre-implementation chain. An agent can still overread a self-declared angle resolution, omit independently discovered coverage from maturation, or conflate user permission to edit with evidence that the model is sufficient.

## What Changes

- Make Model Maturation the sole task-local owner of whether the current model is sufficiently deep for the exact task and claim boundary, before or after implementation evidence exists.
- Add a typed, independent maturation intake that merges task/plan coverage, current-system preflight, unresolved model angles, and only the specialist contributions triggered for the task; candidate models cannot shrink this denominator.
- Require model-angle dispositions that claim resolution to bind current evidence from the declared owner route instead of trusting a caller-authored Boolean.
- Add an internal DevelopmentProcessFlow implementation-admission decision that keeps model sufficiency and execution authorization orthogonal, including exact bounded user authorization with open gaps and explicit invalidation rules.
- Bind Code Structure Recommendation to the exact admitted task/model/coverage scope before its output can be called implementation-ready.
- Require broad Risk Evidence Ledger and Closure Contract confidence to consume the same current task/candidate/coverage-bound maturation result.
- Teach the kernel, existing-model preflight, plan detailing, and triggered specialist skills to exchange typed maturation contributions while keeping each specialist's native semantics and preserving the lightweight path.
- Keep target-software roles and permissions inside the target model; FlowGuard actor kinds remain generic and no public understanding/readiness skill or global product-role taxonomy is added.
- Preserve read-only, trivial, and explicitly scoped use without forcing every task through all specialist routes.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `model-angle-deliberation`: bind claimed angle resolution to current owner-route evidence and project unresolved angles into maturation.
- `model-maturation-iterative`: admit pre-code independent coverage intake and typed owner contributions while preserving one task-local maturation authority.
- `model-maturation-loop`: require the current maturation decision to be consumed by broad downstream claims.
- `development-process-flow`: add internal implementation admission with independent sufficiency and authorization results.
- `pre-implementation-model-hardening`: replace the prose modeling waiver with exact bounded authorization that never upgrades model confidence.
- `risk-evidence-ledger`: add a model-maturation risk gate for broad confidence.
- `flowguard-closure-contract`: require exact current maturation evidence and identity agreement for broad closure.
- `flowguard-ai-entry-simplification`: expose the two-result summary without adding a public route or making lightweight work heavy.
- `flowguard-skill-kernel`: coordinate preflight, specialist contributions, maturation, admission, implementation structure, risk, and closure through current owners.
- `existing-model-preflight`: clarify that full preflight proves the current owner map only and emits maturation coverage contributions.
- `plan-detailing-compiler`: clarify that a reviewable plan is not implementation permission and project task coverage into maturation.
- `code-structure-recommendation`: distinguish an early architecture recommendation from an implementation-ready admitted blueprint.
- `behavior-commitment-ledger`: project only triggered external-promise coverage and gaps into maturation without defining target-domain roles.
- `field-lifecycle-mesh`: project triggered field coverage and gaps into maturation without moving field semantics to the kernel.
- `flowguard-ui-flow-structure`: project triggered UI journey/recovery/blindspot coverage into maturation without introducing a global persona taxonomy.
- `test-evidence-mesh`: project planned, current, stale, skipped, and not-run validation obligations into maturation without treating plans or progress as pass evidence.

## Impact

- Runtime modules: model angle deliberation, model maturation, development process flow, risk evidence ledger, closure contract, public exports, CLI/template projections, and their focused tests.
- Executable FlowGuard models: model-angle deliberation, development-process flow, existing-model preflight/owner handoff, closure, and the affected multi-model authority snapshot.
- Agent guidance: FlowGuard kernel and the existing-model, development-process, code-structure, behavior, field, UI, and test-mesh satellite prompts/protocols.
- Author maintenance and distribution: the FlowGuard SkillGuard contract/manifest, clean consumer projection, local installation, package/version surfaces, Git tag, and GitHub Release.
- Compatibility: current schemas remain latest-schema-first. No compatibility alias, fallback reader, dual authority, new public route, or target-role registry is introduced.
