## Why

FlowGuard 0.68.7 has a statically complete self-blueprint, but the current self-audit only publishes a compact qualification result rather than one independently portable, content-addressed blueprint bundle. The same audit also exposes repeatable route, wrapper, parser, evidence-size, and leaf-test-binding costs that should be reduced before the next patch release. This change makes the existing model/blueprint authority portable and easier to consume, strengthens exact evidence ownership, and performs only proof-backed architecture contraction. It deliberately does not add an independent software-rebuild experiment or make reconstruction a normal workflow.

## What Changes

- Add one canonical, content-addressed portable export for the current self-blueprint, with manifest, shards, model hierarchy, interfaces, intent, resources, code bindings, test/oracle bindings, and rebind verification.
- Expose separate readiness states for static blueprint closure and portable export; keep unexecuted leaf evidence visible instead of treating parent green receipts as leaf proof.
- Add compact summary and candidate-detail projections for ordinary architecture/self-maintenance reads while preserving an explicit full-audit projection.
- Bind existing current test/model receipts to exact behavior blocks and coverage edges without starting one test process per edge.
- Add provider-neutral adapter/conformance requirements for software and non-code workflow targets; do not add Python-only product branches.
- Use the current FlowGuard DNA to review route and step contraction, then retire or merge only candidates with complete caller, consumer, state, error, side-effect, public-surface, model, and test proof.
- First address the six duplicate model runner wrappers and the three strict JSON-key reader implementations when their bindings and parity evidence are closed; leave unresolved candidates retained.
- Update only the affected FlowGuard author skills and references so routing, compact reads, evidence ownership, contraction proof, and final validation order are explicit.
- Keep affected-only validation during implementation, synchronize author/shadow/consumer/install projections after source freeze, and run one final v0.68.8 release parent.
- Do not implement or schedule independent reconstruction qualification, alternate reconstruction paths, compatibility readers, fallback readers, or a second DNA authority.

## Capabilities

### New Capabilities

- `flowguard-portable-dna`: Export and verify one portable, content-addressed current blueprint bundle with explicit static and portable readiness states.

### Modified Capabilities

- `software-blueprint-readiness`: distinguish static readiness from portable export and preserve explicit execution gaps.
- `target-system-blueprint`: require portable export to preserve every declared target-neutral blueprint layer and exact provider identity.
- `architecture-reduction`: make compact candidate/detail reads and proof-backed route/step contraction the canonical cleanup behavior.
- `model-test-alignment`: bind current test receipts to exact behavior blocks and coverage edges without receipt fan-out by assertion.
- `development-process-flow`: make affected-only work, one cleanup pass, late identity freeze, and one final release gate explicit.
- `flowguard-skill-suite-distribution`: synchronize only the affected author skill unit and close source/shadow/consumer/install/release identities for 0.68.8.

## Impact

- FlowGuard blueprint/readiness, target-neutral export, affected projection, model-test alignment, architecture-reduction, and development-process-flow modules.
- The six `.flowguard/*/run_checks.py` wrapper paths and three strict JSON reader implementations, only after evidence-backed rebinding and parity checks.
- The affected `.agents/skills/flowguard*` author sources, references, generated projections, and installation parity records.
- OpenSpec change artifacts and main specifications listed above.
- Version, changelog, adoption, model authority, installation, validation, Git, tag, and GitHub Release identities for 0.68.8.
- No new runtime dependency and no independent reconstruction workspace or reconstruction receipt.
