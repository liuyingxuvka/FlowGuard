## Why

FlowGuard's current workflow can become heavy even when only a small affected slice matters, while some large protocols and fixed distribution details blur responsibility. The workflow should scale its presentation and checks to the task without weakening any triggered obligation.

## What Changes

- Derive ordinary, standard, deep, and release presentations from the compiled demand and risk facts; tiers change ergonomics and aggregation, not correctness.
- Narrow ModelMesh activation to affected related models, parent/child work, stale child evidence, oversized models, or whole-flow claims instead of raw repository model count.
- Split large protocol guidance into conditional references loaded only when their trigger applies.
- Remove fixed satellite-count and installation ownership from DevelopmentProcessFlow; it consumes typed distribution evidence owned by SkillGuard/installation workflows.
- Keep RiskLedger as the broad-confidence owner and ClosureContract as a thin terminal integrity check.
- Make the primary AI route read as one understandable sequence: freeze facts, derive demand, resolve owners, mature, verify, then separately admit implementation.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `flowguard-ai-entry-simplification`: Presents one adaptive model-first sequence with derived cost tiers and explicit skipped/not-run gaps.
- `hierarchical-model-mesh`: Uses affected topology rather than raw repository model count as its activation boundary.
- `development-process-flow`: Consumes typed distribution evidence without owning a fixed skill inventory or installation procedure.
- `flowguard-skill-suite-distribution`: Owns current suite identity and clean installation evidence independently of development admission.
- `flowguard-closure-contract`: Remains a thin integrity wrapper around the RiskLedger decision and shared evidence identities.

## Impact

This changes the main FlowGuard skill prompt, selected satellite protocols, routing language, development-process evidence inputs, self models, and workflow tests. It does not add a separate public understanding skill or a user-selectable weak mode.
