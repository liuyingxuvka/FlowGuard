# FlowGuard self-maintenance performance model miss

## Observed miss

The first standalone self-architecture-reduction audit rebuilt the complete self-blueprint and then scanned every member against every implementation surface. After more than forty minutes it still had not reached a terminal result. The verified process tree was stopped with zero descendants remaining, so that interrupted run is invalid evidence and is not reused.

The first long-root full-model proof also exposed a Windows path-length failure inside nested shard-safety evidence. The models themselves passed, but the evidence path could not be materialized and therefore the parent run correctly failed.

After compact projection and one-time immutable-report fingerprints were in place, the real composed audit exposed a third independent amplification: normalization materialized the same canonical logical payload as several complete JSON byte strings while retaining the physical projection. The process reached about 5.2 GB and was stopped after 272.317 seconds with exit `-1`; its exact process tree was verified empty, so this run is also invalid and non-reusable.

## Exact correction

- Build one reverse caller index and reuse it for every reduction candidate instead of rescanning all surfaces for every member.
- Let the composed self-maintenance command build the self-blueprint once and pass that exact in-memory bundle into architecture reduction.
- Merge the duplicate release owners into one `self_maintenance_review` owner while retaining both validation obligations.
- Use deterministic short internal shard-safety directory names while retaining the full model identity in receipts.
- Project compact self-maintenance fields directly instead of expanding multi-gigabyte full payloads and then discarding them.
- Compute the immutable large behavior-report fingerprint once and reuse that exact canonical value across blueprint and reduction consumers.
- Stream canonical fingerprint and byte-count computation for large normalized payloads, release each logical payload before constructing the physical projection, and never retain several complete serialized copies at once.
- Keep this correction limited to the declared performance boundary; it does not introduce a new qualification gate or a global blueprint cache.

## Evidence boundary

The last pre-correction full regression covered all 65 registered models under one terminal parent receipt, including serial and parallel shard-safety checks beneath the intentionally long evidence root. This new normalization correction requires renewed affected and full evidence before release. The release claim still requires the composed real self-maintenance audit, current model-authority activation, SkillGuard validation, distribution parity, and the final foreground release gate.
