## Why

FlowGuard's canonical behavior model is language-neutral, but the current whole-project blueprint path still hard-codes Python discovery and can report a broad `ready` result from owner-wide semantics and prepared-but-not-executed generic test designs. FlowGuard must instead expose one target-system blueprint contract that can describe software in any language, non-code workflows, and mixed systems while telling AI exactly which understanding layer is proven.

## What Changes

- Introduce one provider-neutral target-system blueprint contract above source-language and workflow adapters.
- Make Python source discovery one registered provider rather than a core admission rule; missing providers remain explicit gaps without making the target kind unsupported.
- Separate evidence qualification, static blueprint readiness, and task admission in APIs, CLI results, AI understanding projection, and release evidence.
- Require behavior-block-local semantics, explicit portable state/transition/property bindings, independently justified helper relations, and concrete good/bad/boundary case designs.
- Bind real test nodes, assertions, cases, or native checks to exact behavior blocks; aggregate or owner-wide evidence remains supporting only.
- Use the rich model-intent inventory as the sole intent authority and project WorkContext, OpenSpec, Spark/OpenSpark, changelog, and user decisions into exact target/model obligations.
- Keep ordinary work affected-only and token-bounded; full target-system qualification remains explicit.
- Expand FlowGuard self-reduction discovery to duplicate routes, branches, adapters, facades, helpers, and validation paths while preserving the equivalence-proof gate.
- Make the explicitly selected composed self-maintenance path build the exact self-blueprint once, reuse it for reduction review, and pre-index caller relations once instead of rescanning the whole surface inventory per candidate; fingerprint mismatch SHALL force a rebuild.
- Update the maintained FlowGuard skill suite, clean consumer projection, installation, release validation, and patch-version publication.
- **BREAKING** Replace the Python-only blueprint-definition/CLI language gate with direct-current target-kind and provider identities; no compatibility reader or alias remains.

## Capabilities

### New Capabilities

- `target-system-blueprint`: Provider-neutral target-system inventory, behavior DNA, layered readiness, compact understanding projection, and mixed-provider composition.

### Modified Capabilities

- `software-blueprint-readiness`: Software-project qualification becomes one target-system specialization and cannot close from generic owner semantics or synthetic test placeholders.
- `authoritative-model-system`: Observed model authority binds target-system blueprint identities and exact provider/resource/intent lineage.
- `model-test-alignment`: Blueprint alignment requires exact behavior-block/test/assertion/case/oracle bindings and preserves planned versus current execution separately.
- `architecture-reduction`: Self-reduction derives a broader duplicate-path denominator without authorizing contraction absent equivalence or facade proof.
- `flowguard-ai-entry-simplification`: AI receives one compact depth/readiness/first-gap view without loading the full blueprint.
- `flowguard-skill-kernel`: The kernel routes target-system blueprints independently of language and exposes only the understanding needed by the selected task.
- `development-process-flow`: Lifecycle and release gates freeze the target-system/provider identities and preserve the three readiness claims independently.
- `work-context`: Provider-neutral planning and workflow material projects exact target-system intent without becoming behavior or test evidence.
- `flowguard-skill-suite-distribution`: Maintained prompts and clean consumer projections expose the same target-system and readiness semantics.

## Impact

- Core modules: blueprint readiness, project/target composition, implementation and test inventories, intent projection, understanding readiness, CLI, self-blueprint, self-reduction, and the shared self-maintenance execution path.
- Model authority: the implementation-blueprint, model-test-alignment, architecture-reduction, understanding, model-mesh, and development-process owners plus one accepted whole revision set.
- Maintained skills: FlowGuard kernel and the affected preflight, structure, mesh, alignment, reduction, test, and lifecycle satellites under SkillGuard author supervision.
- Tests/docs/distribution: new declared-workflow and non-Python provider fixtures, stronger counterexamples, updated public API/docs, installed skill sync, shadow parity, patch tag, and GitHub Release.
