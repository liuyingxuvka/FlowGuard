## Context
The existing accepted model and native evidence are retained. This integration connects actual functional goals, responsibility semantics and task sufficiency to public reads, while eliminating unrelated comparisons and repeated selected-scope reconstruction.

## Goals / Non-Goals
Goals: verified current functional outcomes, precise growth and missing-evidence pointers, scoped architecture judgment, exact affected owner reuse, and bounded internal paging within one selected batch.
Non-goals: universal automatic architectural rewrites, PlanningTool edits, a new public lifecycle operation, historical compatibility readers, or treating default token/time limits as functional completion.

## Decisions
1. Authenticate original model-native leaf receipts separately from receipt-free architecture material. Production source fingerprints remain separate from native owner execution fingerprints.
2. Index related semantic contexts, preserving every relevant obligation and hard semantic difference; unrelated contexts produce no comparison.
3. Bind owner coverage resolutions to the original demand basis, derive one exact closed demand, and verify both identities independently.
4. Produce authentic task maturation through one explicit domain producer. Public reads only consume verified contexts and return precise evidence gaps.
5. Observe only declared finite changed paths. Unknown or incompletely bound paths remain visible gaps until independent inventory and binding evidence closes them.
6. Reuse a selected read context and check its original raw inputs once at batch completion. Internal pages remain bounded; no cross-invocation cache is introduced.
7. Preserve explicit supervision, full-validation authorization and separate publication/installation evidence. Default light operation/time ceilings are unset.

## Risks / Trade-offs
- Strict evidence joins can reveal previously hidden gaps. Missing evidence stays explicit and is never converted into a pass.
- Native context construction must avoid receipt self-reference. Independent finite fixtures and real producer/verifier APIs provide this boundary.
- Parallel changes share integration interfaces. Workers own disjoint files; the integrator alone owns shared contracts, lifecycle entry points and stateful validation.
