## Why

The current selected software map can place useful functional understanding behind many structural pages; the audited read exposed its summary only on page eleven. A normal read should expose the selected current state, target and gap denominators, actual first gap and next owner on its first page, so the caller can identify the evidence needed for the task without requesting the entire closure by default.

Missing task facts currently risk looking like a proven empty set when absent ID fields are counted as zero. Navigation must distinguish unobserved denominators, temporary compromises, unknown coverage and scoped-out surfaces while preserving the original task verdict.

## What Changes

- Add a derived understanding summary over the complete selected material, retaining the existing current, target, gap, action and scope fields.
- Expose selected-model and target counts; requested, satisfied, missing, required-obligation and required-owner counts; separate observation, improvement and growth gaps; and separate unknown and scoped-out surface counts. Task counts are null when their original ID collection is absent or unobserved.
- Expose typed temporary-compromise counts and exact detail references, and retain the actual first-gap row, available raw reference and responsible owner.
- Prioritize summary and functional navigation in the existing bounded transport. Report decision-basis availability separately from complete-detail transport, and preserve lossless cursor and explicit full-batch behavior.
- Update the existing consumer protocol to start with the first page and fetch current details that can change the verdict. Retain explicit full-batch reads for tasks requiring the complete selected closure.
- Add the eight planned acceptance cases and retain the existing read-boundary regressions. Close this implementation change from actual scoped Source checks; track final native qualification, model acceptance, full validation and delivery separately through the goal and DevelopmentProcessFlow.

None. Existing task understanding, architecture confidence, selected-read authentication and stopping requirements remain in force; this capability adds a read presentation contract.
