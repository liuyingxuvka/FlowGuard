## Context

Selected reads already authenticate one accepted head, its selected source material, immutable architecture details and an optional original task context. Their current transport can deliver structural records before useful summary and functional records. The R11 change alters that presentation using material already loaded by the same invocation.

The existing successful functional projection supplies requested, satisfied, missing, required-obligation and required-owner ID collections. Authentic blocked diagnostics can omit some of them. Required obligations originate in actual outcome/code/native joins and cannot be reconstructed from coverage-demand IDs, gap labels or action strings.

## Goals / Non-Goals

**Goals:**

- Make first-page current/target/gap/compromise/unknown navigation useful within the complete selected denominator.
- Preserve original task verdicts, deepest proven layer, typed gaps, exact references and finite scope.
- Distinguish available decision material from complete selected-detail delivery.
- Keep ordinary reads read-only and retain the existing page bound, cursor binding and one-projection/one-final-guard batch behavior.

**Non-Goals:**

- No new functional completion or architecture-confidence algorithm.
- No new authority, producer, scanner, historical traversal, fallback or compatibility route.
- No default full-batch requirement or arbitrary cost, token, model-count, operation or iteration cap.
- No product-specific scope, normative target extension or additional validation owner.

## Decisions

1. **Derive the summary from complete selected material.**
   Pass the actual selected IDs into the existing summary function. Keep current/target/gap/action/scope and add denominator, compromise and navigation groups. Count distinct original IDs from the complete material, never from a page slice. Retain separate observation/improvement/growth and unknown/scoped-out counts. The five task counts are integers only when their original values are lists or tuples; missing, null or unobserved collections produce null. A genuine empty collection still produces zero.

2. **Use typed pointers and original diagnostic rows.**
   Classify temporary compromises using the authenticated pointer kind and existing reference checks, preserving exact original detail references and review conditions. Copy the original functional first gap when available; otherwise use the actual typed growth gap. Keep unresolved structural detail visible when no original gap row is available. Use an original raw reference or bytes already materialized in the invocation; an absent file receives no invented fingerprint. Take next owner from the original first-gap owner or typed pointer owner fields, never an action-string prefix.

3. **Preserve the original verdict.**
   Navigation carries the original stopping disposition; no task context retains the existing not-evaluated state. Original functional-scope and deepest-layer algorithms remain unchanged. Unknown architecture or compromise counts remain visible alongside the authentic task verdict. A compromise never adds a satisfied outcome or creates a closed verdict.

4. **Prioritize navigation within existing transport lanes.**
   Place summary metadata and functional records before other relations, then continue original growth, architecture and map material. Prioritize relations before intents in context pagination while retaining all six cursor positions. Full lists and exact evidence records travel once under the existing tags; only small selected denominators, first-gap navigation and transport metadata repeat. Existing head/scope/digest validation continues to reject foreign or modified cursors.

5. **Separate decision material from detail completeness.**
   Expose prepared record totals and actual transported counts. decision_basis_complete requires the actual current/scope/denominator/navigation material and original stopping basis; null task denominators or unresolved gap detail keep it false. A missing raw file can retain its authentic missing-path gap without a fabricated reference. details_complete is true only when the returned material reconstructs all selected detail. A terminal suffix page is incomplete; an explicit complete batch becomes complete only after every lane and summary/functional record matches the prepared full projection.

6. **Retain bounded observation and native ownership.**
   Every JSON page plus newline stays within 8192 UTF-8 bytes. An indivisible record exceeding the limit remains an explicit error; its reason, obligations and references are never truncated. Explicit batch prepares once and performs one final drift guard; separate cursor invocations observe current state afresh. Read executes zero producers and performs zero authority writes. Changed-input qualification and completion use the existing native owners and actual current receipts.

## Risks / Trade-offs

- Wide selected material cannot fit all IDs on the first page. Complete counts and original navigation remain visible while exact details use existing cursors/references.
- A blocked or invalid task context lacks some denominator fields. Null values and a false decision-basis flag prevent an empty-set claim; the original failure remains visible.
- Reordering records changes page boundaries. Independent full-payload oracles, cursor rejection and reconstruction checks protect losslessness and the existing byte limit.
- A-stage receipts describe the earlier Source. B-stage acceptance requires fresh changed-input qualification and current native evidence; prior full success cannot be relabeled.
