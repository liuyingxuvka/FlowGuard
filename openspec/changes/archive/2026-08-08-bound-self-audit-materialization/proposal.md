## Why

FlowGuard's self-DNA is now deep enough that the existing audit path repeatedly observes, expands, fingerprints, and publishes the same governed facts. The repetition does not add independent authority; it makes a complete self-audit unnecessarily slow and can amplify exact ambiguity and review data into very large in-memory and terminal payloads.

## What Changes

- Reuse one immutable implementation-source observation bundle inside a single self-blueprint build while preserving independent classification, denominator, and readiness decisions.
- Make the blueprint builder carry the exact identity of the inputs it actually consumed, then perform one final fresh identity comparison before publication instead of performing a second result build.
- Aggregate ambiguous call evidence without repeating the same candidate set for every caller, while retaining every exact caller, candidate, and blocking ambiguity.
- Construct normalized and architecture-review identities once and separate the full review identity from the bounded publication identity.
- Cache each large immutable blueprint identity inside its owning invocation, index model-test blockers once, and validate each affected shared object once before reusing that exact computed fingerprint.
- Replace candidate-wide repeated set construction and conflict rescans with exact one-time indexes while preserving every candidate and blocker.
- Materialize exact-current contracts automatically for statically finite dynamic selector operations, while keeping truly open selectors blocked unless they have an explicit bounded contract.
- Keep behavior-coverage ownership, native check execution ownership, and terminal receipt evidence as separate facts; ordinary supporting tests with no exact behavior edge remain valid supporting evidence rather than thousands of false missing-owner findings.
- Store each exact coverage-derived candidate evidence neighborhood once in a content-addressed catalog, let candidates carry only its direct current reference, and fail closed when that reference is absent, duplicated, stale, or inconsistent with the resolved full observable contract.
- Make release validation compute the complete self-maintenance review but publish its bounded compact projection.
- Remove the unused supplied-blueprint path that rebuilds the same blueprint and compares two complete payloads.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `architecture-reduction`: Require one complete composed review, one final exact input-currentness comparison, aggregation of logically shared ambiguity evidence, and distinct full-review versus compact-projection identities.
- `software-blueprint-readiness`: Require invocation-local observation reuse and single-owner normalized reference materialization without weakening independent completeness checks.
- `flowguard-skill-suite-distribution`: Require the release owner to consume the complete self-maintenance decision through a bounded compact result.
- `model-test-alignment`: Require blocker findings to be indexed once for exact model/code/test binding lookup instead of rescanning the complete finding set per binding.

## Impact

The self-blueprint discovery path, Python implementation observation, dynamic-selector contracts, implementation and test inventories, model-test alignment, normalized and affected blueprint compilers, self-architecture reduction review schema, candidate evidence-neighborhood representation, compact projection, release-suite command composition, focused performance regressions, and architecture-reduction model authority are affected. Public domain semantics and audit denominators do not shrink; this change removes false gaps and duplicate physical representation without converting supporting evidence into invented behavior ownership.
