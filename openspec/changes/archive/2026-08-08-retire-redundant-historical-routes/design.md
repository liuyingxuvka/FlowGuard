## Context

FlowGuard now has a current hierarchical software blueprint, explicit structural/cross-boundary topology, per-behavior input/state/output/effect/terminal contracts, code and test bindings, affected-model propagation, a behavior commitment ledger, canonical finite contract cases, model maturation, and release evidence owners. Several older product routes predate that structure and repeat one part of it through a separate report, search loop, template, public route, or self-model owner.

The current Architecture Reduction implementation authorizes contraction only through observable equivalence or a public facade. The main specification already anticipates replacement or retirement dispositions, but runtime types, self-reduction evidence, BCL accounting, and tests cannot yet express intentional removal of behavior. This gap must be closed before deleting historical functionality.

The worktree contains concurrent AI work and a dirty external shadow repository. All edits and synchronization must remain path-owned, and the final release must be produced only from one frozen integration snapshot.

## Goals / Non-Goals

**Goals:**

- Make “is this behavior still necessary for the current DNA goal?” a first-class reduction decision.
- Preserve useful protections under one current owner while deleting duplicate routes and public surfaces.
- Reduce repeated repository search, open-ended reflection, universal template work, model owners, API exports, CLI choices, and maintenance obligations.
- Make FlowGuard's self-cleanup a real use of its general DNA/reduction path, with complete model/code/test/interface accounting.
- Leave one direct current path and visible failure for retired or unresolved identities.

**Non-Goals:**

- Deleting historical changelog entries, archived OpenSpec changes, immutable old model snapshots, or release receipts; those remain non-current history.
- Retiring the core topology-hazard protection set in this patch. Its independent public route can be reconsidered only after every negative case has been reattached and proved under canonical owners.
- Removing Model Miss, finite same-class cases, ModelMaturation, KnownBadProof, affected topology, BCL, model/code/test bindings, or evidence freshness.
- Replacing retired routes with aliases, compatibility readers, a second migration workflow, or another umbrella skill.
- Treating public-surface shrinkage as evidence that downstream external consumers have accepted unrelated breaking changes.

## Decisions

### Add `retire_behavior` to the existing reduction owner

The existing Architecture Reduction data path will gain a typed behavior-retirement disposition. It will carry current-goal rationale; retired commitment and behavior-block identities; replacement/absorbing owner identities when applicable; API/CLI/skill/prompt/code/test/model/topology/consumer dispositions; required affected routes; governed fingerprints; and an independently reviewed proof status.

The reducer will continue to require equivalence for `contract`. It will allow changed observable state/effects only for `retire_behavior`, and only when the complete responsibility/consumer inventory has a disposition. Missing current ownership, unknown consumers, stale inventories, or dangling negative cases block authorization.

Alternative rejected: add a new “feature retirement” skill. It would create another route for the same architecture decision and contradict the reduction goal.

Alternative rejected: interpret an existing unresolved or deletion action as retirement. That would hide the product decision and make it impossible to distinguish unproved deletion from an authorized behavior change.

### Migrate protections before deleting leaf routes

Each retired route will have a protection ledger derived from its native model cases, tests, BCL commitments, route relations, and ordinary production consumers. Every useful protection must first have one current owner and executable evidence. Only then are the old implementation, public surface, dedicated tests, model owner, manifest row, semantic-mesh node, blueprint block, spec, and prompt removed together.

The first high-confidence leaf batch is:

1. Model Angle Deliberation → concrete gap types move directly into TaskCoverageDemand and ModelMaturation; Existing Model Preflight stops importing or carrying angle reports.
2. Maintenance Scan Router → typed findings/obligations go directly to DevelopmentProcessFlow, ModelMaturation, ArchitectureReduction, StructureMesh, or their specialist owner; `MaintenanceObligation` remains in its existing independent owner module.
3. Model Similarity Consolidation → the large review/plan engine is replaced by the minimal immutable relation handoff already consumed by canonical owners; there is no standalone public route, review report, template, or completion claim.
4. Legacy Compatibility Cleanup and Template Harvest Closure self-model owners → required negative cases move to current ArchitectureReduction, DPF/SkillGuard, MinimumModel, and conditional template-library owners before the old children leave the current manifest.

Alternative rejected: delete modules first and let failing tests reveal protection ownership. Tests are not a complete responsibility inventory and this would make absence, rather than model evidence, drive architecture.

### Make bug back-propagation one bounded path

Model Miss will locate the exact current commitment and behavior block, classify why the model missed the problem, and contribute observed and finite same-class seeds to ContractExhaustion. ContractExhaustion becomes the sole current case authority. Model/code/test bindings and the canonical affected topology are replayed, and ModelMaturation emits one closure result consumed by the risk ledger.

Legacy defect-family, analogous-scan, and same-class closure wrappers will either become internal projections of those canonical case identities or be removed. UI-specific miss records and BCL backfeed remain with their actual owners.

“Similar bug” scope is limited to explicit `affected_sibling`, same-intent, shared-owner, shared-mechanism, or other canonical relations. The workflow no longer repeats free-form repository scans to prove that it searched enough.

### Make template work opt-in or evidence-triggered

Minimum model confidence will retain protected-error intent, state/effects, completion evidence, executable known-bad proof, and current bindings. Template search/no-match/harvest is removed from the universal minimum contract and shared runner sections.

The template library remains available for two triggers only: an explicit reuse/publication request, or a bounded stable pattern supported by current executable evidence and intended for cross-project reuse. Existing explicit template-library behavior remains strict once triggered.

Historical model snapshots and adoption logs that mention harvest remain immutable history. Current runtime, generated templates, skills, and self-model authority stop treating them as required gates.

### Split current modeled lookup from unmodeled adoption

Existing Model Preflight will have two visible states:

- `modeled_current`: exact observed authority, commitment owner, affected blueprint ids, and canonical relations are available.
- `adoption_candidate`: no current DNA exists, so bounded project discovery may propose candidate files/owners but cannot claim understanding or implementation readiness.

The existing `fallback` status, root-model substitution, and model-like file promotion are removed from modeled-target authority. A blocked modeled lookup stays blocked.

### Remove dated task instances from the current self-DNA

A model may remain useful as immutable historical evidence without remaining a current software owner. The current self-model universe therefore rejects a model whose purpose is bounded to one past version, one dated documentation request, or one completed release operation when continuing canonical owners already cover its reusable protections.

The second cleanup batch is explicit:

1. `readme_positioning_20260602` retires. Its pain-first/no-overclaim writing intent remains in the README and historical change evidence, while documentation validation and publication ordering remain with their current test and DevelopmentProcessFlow owners.
2. `release_visibility_process` retires. Its generic source/install/tag/release freshness and peer-preservation protections already belong to `development_process_flow`; release-verification implementation surfaces transfer to that continuing owner.
3. `risk_purpose_header` retires. Required purpose declarations and template/header assertions remain under the minimum-model/kernel and template tests, while broad release evidence remains under DevelopmentProcessFlow. Its former code ownership is reassigned to the exact continuing risk, template, and closure owners rather than leaving a historical rollout as a catchall.
4. `openspec_archive_cleanup` retires. OpenSpec retains native archive lifecycle authority; FlowGuard's reusable order, freshness, test-mesh, install, and peer-preservation protections remain with DevelopmentProcessFlow and TestMesh, and the OpenSpec verification scripts attach as supporting implementation surfaces rather than a second archive authority.

Every retirement first receives a complete model/code/test/commitment/topology/consumer/negative-case disposition. The current manifest, semantic mesh, software blueprint, BCL, intent denominator, and observed authority are rebuilt from the reduced continuing universe. The archived models and prior receipts remain immutable history but are not loaded, replayed, or used as current intent.

The retained `minimum_valuable_model_entry` is repaired in the same batch. Its executable state machine must accept an ordinary protected-error model with completion and known-bad evidence without running template search or harvest. Template reuse remains a separate explicit route; leaving the old universal template state machine in the current model would make the specification say one thing while FlowGuard's own DNA says another.

Alternative rejected: rename the four historical models and keep their old state machines. A new label would not remove the version-specific purpose, duplicated release/archive steps, or incorrect current ownership.

Alternative rejected: delete the model files but keep their production-code overrides. That would leave a hidden historical owner in the blueprint and make the reduced denominator dishonest.

### Shrink public and model surfaces in one coordinated disposition

Retiring a route removes its top-level exports, route API group, starter/advanced registry entry, CLI/template command, route profile, prompts and skill references, API documentation, direct tests, current BCL commitments, self-model owner, manifest entry, semantic-mesh node/relations, and software-blueprint binding. Small shared data carriers remain only under the canonical owner module and are not re-exported as retired routes.

Duplicate `*-full-template` commands that produce the same public route workflow as the canonical template will be removed in the same direct-current style. The canonical template remains; an old name is an error.

The current self blueprint is regenerated from the reduced universe rather than manually retaining deleted blocks. Current model intent and observed authority are rebuilt only after OpenSpec archive path movement, because archive changes source identities.

### Separate completed construction models from permanent capability models

Five additional current children are completed construction histories, not
continuing software-DNA owners:

1. `ai_surface_streamlining` delegates current lightweight routing to the AI-entry/kernel owners and typed relations to CanonicalRelation consumers. Its old protection that the full standalone ModelSimilarity schema must remain is now obsolete and is retired explicitly rather than migrated.
2. `reduce_architecture_surface` is a completed public-facade contraction. Public API parity and manual-export negative cases move to ArchitectureReduction; install, shadow, and evidence freshness stay with DevelopmentProcessFlow.
3. `simplify_flowguard_structure` is a completed structure pass. CLI/template parity moves to StructureMesh, facade parity to ArchitectureReduction, and peer/sync/progress evidence to DevelopmentProcessFlow and TestMesh.
4. `structure_surface_simplification` is a completed combined rollout. Template parity, evidence-stream honesty, native-runner authority, payload deduplication, recoverable evidence lifecycle, and shadow freshness become separate exact failures under their permanent owners.
5. `simplify_field_schema` merges its fallback-residual and broad-regression protections into `default_replacement_field_lifecycle`, which already owns single-path field replacement and a wider current negative-case set.

Their model directories, manifest members, semantic entries, blueprint
composites, and current intent bindings are removed only after the replacement
negative cases pass. Archived OpenSpec, adoption logs, old snapshots, and model
revisions remain immutable history and are excluded from current authority.

Three children remain necessary but currently model the act of upgrading
rather than the resulting capability:

- `validation_evidence_gates` becomes the long-term owner for evidence
  primitives, lifecycle, receipts, terminal/current-head binding,
  stale/skipped/not-run/progress visibility, validation ownership, and proof
  fingerprints. UI click-through, payload-domain semantics, manual
  operability, and installation move to their existing specialist owners.
- `user_facing_model_diagrams` becomes the long-term owner for deterministic,
  safely escaped Mermaid export and optional route-specific explanatory
  guidance. A diagram explains a model but never changes a checker result or
  substitutes for evidence.
- `codex_skill_satellites` becomes the dynamic suite-topology owner. Member
  identities, roles, required files, and counts derive from the canonical
  suite map; source, formal, shadow, installed, clean-consumer, version, and
  release identities remain separate evidence. Fixed count literals are not
  authority.

For all three, manifest inputs expand from self-only model/runner files to the
real code, tests, specs, prompts, and authoritative maps they claim. The
software blueprint narrows catch-all ownership: suite topology does not own
the entire package facade, CLI, or every route template body merely because it
distributes them.

Alternative rejected: delete all eight because they have rollout-shaped state.
The latter three own current implementation surfaces with no equivalent single
owner, so deletion would create a real DNA hole. Alternative rejected: retain
all eight and merely refresh hashes. A fresh hash over a completed construction
script still does not make it a current capability model.

### Contract retained routes at step level, not only at route level

A route can remain necessary while some of its internal work is obsolete. The reduction inventory therefore treats a branch, scan, reflection pass, helper chain, evidence projection, repeated fingerprint, or large materialized payload as a first-class candidate. Each candidate must name the exact current obligation it protects, its unique owner (if any), its callers, negative cases, side effects, and measured or structurally bounded cost.

If another exact-current owner already supplies the same result and evidence, the duplicate step is removed or delegated to that owner. If the work is useful only for an explicit deep analysis, reuse, publication, or user-requested operation, it moves behind that explicit trigger instead of remaining on the ordinary path. If it has no current consumer or protection, it is retired. If it is the sole safety classifier, failure oracle, source verifier, or terminal evidence producer, it remains until a proved replacement exists.

Cost evidence may be operation counts, repeated full-denominator scans, duplicate source reads, repeated canonical serialization/fingerprinting, physical payload growth, token-facing projection size, elapsed time, or validation-owner duplication. Cost alone never authorizes removal; necessity and replacement ownership decide the action, while cost decides priority and whether an optional step should be on-demand.

Alternative rejected: only delete whole modules. That would leave the main source of ongoing bloat—duplicated work inside retained routes—untouched.

Alternative rejected: remove every expensive step. Some expensive work is the unique proof producer for a hard invariant; such work stays and may only be partitioned, cached over an immutable identity, or moved to the exact release/deep-analysis boundary that consumes it.

### Consume the coordinated per-model path-quality owner

This retirement change depends on `require-per-model-path-quality-closure` for every continuing or materially changed FlowGuard self-model. ModelMaturation remains the sole single-model path-quality owner; this change consumes its compact current result when prioritizing and proving self-model or mapped implementation contraction. It adds no second optimizer, result schema, public route, skill, reconstruction branch, or authority pointer.

Tasks 4.5, 4.7, and 4.8 use those current results during compact self-audit and internal contraction. The final whole-system claim requires zero unresolved required path-quality rows after the continuing model-owner denominator is frozen, while ordinary unrelated affected-only work remains narrow.

### Make BCL source freshness executable rather than self-declared

The existing Behavior Commitment Ledger remains the sole behavior-source
accounting owner, but its current source rows must be derived from real project
files. The owner will resolve each semicolon-separated source reference, strip
only its non-path anchor, expand only bounded project-relative globs, normalize
to sorted unique POSIX paths, and fingerprint every file with FlowGuard's
existing canonical source-byte policy. A single file keeps its canonical file
fingerprint; a composite source uses one canonical ordered file-identity
aggregate. The top inventory identity is then derived from the complete sorted
surface inventory rather than written independently.

Ledger review for a broad claim will compare the checked-in source rows with a
fresh read of the same project root. Missing paths, empty or escaping globs,
unsafe links, changed files, changed composite membership, stale row hashes, or
a stale top inventory revision are blockers. The existing ledger owner may
produce a refreshed immutable ledger value, but no review path silently
rewrites it and no caller can mark a row current without the same derivation.
Authored semantic fingerprints and commitment decisions remain authored; the
mechanical refresh owns only physical source identity and discovery evidence.

Alternative rejected: add a separate BCL compiler route or trust
`freshness_state=current`. A second scanner would create duplicate authority,
while a handwritten status cannot prove that the source still matches.

The refresh also must not preserve an incorrect ownership boundary merely
because the referenced file can be hashed. BCL owns external promises and the
normative sources from which those promises are derived. Production modules,
helper modules, executable self models, and test files are implementation or
evidence surfaces; their exact code/test relationship belongs to the software
blueprint, implementation inventory, Model-Test Alignment, and TestMesh. The
current FlowGuard ledger's implementation-like source rows will be replaced by
current normative OpenSpec or public contract sources before those code rows
are removed. A commitment may then cite both its normative BCL source and its
separate blueprint code/test bindings without either owner copying the other.

Alternative rejected: keep code rows in BCL as convenient backlinks. That
would make implementation describe its own external promise, duplicate the
blueprint, and allow a mechanically current file hash to masquerade as proof
that the behavior itself is intended.

The FlowGuard self-ledger transfer is exact:

| Current implementation/test row group | Current normative owner after transfer |
| --- | --- |
| UI content model and test rows | existing `flowguard-ui-flow-structure` spec and UI skill contract |
| WorkContext model, code, and test rows | `work-context` spec |
| Process-strategy model, code, and test rows | `development-process-strategy-selection` spec |
| BCL implementation and BCL test rows | existing BCL spec plus the exact ContractExhaustion/TestMesh/ModelMiss skill or spec source already attached to each promise |
| Self-maintenance implementation, model, and test rows | `flowguard-self-maintenance-mesh` spec; single-path replacement also retains the project rule and hard-gate document |
| Task-demand implementation row | `task-coverage-demand` spec |
| Maturation-receipt implementation row | `model-maturation-receipt` spec |
| Implementation-admission implementation row | `development-process-flow` implementation-admission requirements |
| Understanding-confidence implementation row | `risk-evidence-ledger` spec |
| Understanding-closure implementation row | `flowguard-closure-contract` spec |

The removed implementation and test paths remain exact blueprint and TestMesh
members. The transfer therefore shrinks BCL's token and ownership surface
without weakening code or test traceability.

### Make strategy selection derive the work order instead of endorsing it

The existing DevelopmentProcessFlow `strategy_selection` mode already checks
hard outcome equivalence, dependency cycles, safe-parallel evidence, freshness,
and bounded optimality language. It does not yet choose between eligible work
orders: the caller supplies `selected_candidate_id`, and the current reviewer
will accept either of two otherwise valid candidates even when one repeats
derived-document writes after a later source change. That is validation of a
choice, not model-guided ordering.

Each candidate will therefore bind every step to the artifacts it reads,
writes, and invalidates, plus comparable step, coordination, and side-effect
cost units when measured comparison is claimed. The reviewer will first reject
cycles, an execution sequence that contradicts its dependency edges, missing
step/artifact identities, and non-equivalent candidates. For the remaining
finite candidates it will derive a structural score from invalidated outputs,
repeated writes, repeated validation, coordination, side-effect exposure, and
declared comparable effort. It will select the unique lowest score itself. A
caller-supplied selection may request or reaffirm the result but cannot make a
higher-cost candidate pass as preferred.

A tie remains visible and requires an explicit evidence-backed choice; it is
not broken silently. Qualitative evidence supports only a current preference.
Measured inputs over an exhausted named finite set may support a minimum within
that set. Neither path claims a global optimum or invents schedules outside the
declared candidates. Ordinary one-route work still returns `not_needed` and
carries no optimizer payload.

This remains an internal mode of DevelopmentProcessFlow. No new public skill,
route, model owner, compatibility reader, alternate command, or second process
authority is added.

## Risks / Trade-offs

- **A historical route has an undocumented external consumer** → Compile exact in-repository callers and public-surface commitments, document the intentional patch-release breaking boundary, and block a candidate if a current declared consumer lacks a disposition. Do not add compatibility.
- **A useful negative case disappears with its model owner** → Require manifest-level failure-obligation mapping to a current child before deletion and run the new owner case first.
- **The first cleanup batch becomes too broad to validate** → Keep candidate dispositions independent and affected-route scoped; unresolved candidates remain explicit rather than being forced into the patch.
- **Removing universal template gates changes old runner schemas** → Accept current fields only where they remain meaningful to explicit template work; remove them from canonical completion requirements and generated output without introducing dual schema authority.
- **Self-blueprint and semantic mesh counts change widely** → Treat the reduced owner set as an intentional authority migration, regenerate derived projections once, and validate zero dangling identities before the final parent run.
- **A locally redundant-looking step is the only real guard** → Require exact obligation, caller, negative-case, and evidence-owner accounting before step contraction; missing ownership leaves a typed unresolved candidate.
- **An optional deep step leaks back into ordinary use** → Bind its explicit trigger and add a regression proving the lightweight path neither executes it nor emits its large payload.
- **Archived evidence contains retired identities** → Keep it immutable and clearly non-current; current inventory scanners must exclude evidence/archive roots from authority.
- **Concurrent edits change a candidate after audit** → Recompute the affected inventory and governed fingerprints immediately before applying each retirement and before publication.
- **Patch release contains intentional breaking contraction** → State the exact removed routes/commands in the changelog and release notes; the version bump remains user-directed while compatibility is intentionally not preserved.
- **Declared cost data is incomplete or incomparable** → Keep the decision blocked or qualitative; never accept a caller-picked route as a measured minimum merely because it supplied a rationale.
- **Several finite candidates have the same derived score** → Expose the tie and require current tie-break evidence instead of silently using declaration order or lexical id.
- **A current model watches only its own model and runner** → Expand its manifest inputs to every real source/spec/test/prompt/map that can change the claimed behavior; self-only freshness cannot support current DNA.
- **A retained model still contains rollout milestones** → Rewrite it around runtime or ongoing process inputs, states, outputs, failure boundaries, and current evidence before accepting its purpose closure.

## Migration Plan

1. Add `retire_behavior`, retirement proof, BCL/consumer disposition, and native bad cases to Architecture Reduction before any behavior removal.
2. Build a machine-readable protection ledger for the selected leaf routes and map every retained negative case to one canonical current owner.
3. Make template work conditional, make model-miss same-class evidence canonical, and remove modeled-target fallback so replacement owners are direct-current.
4. Run focused new-owner tests and model cases; unresolved protection mappings stop the corresponding candidate only.
5. Remove each authorized leaf route across implementation, API/CLI, skills/prompts, specs, tests, BCL, model inventory, semantic mesh, blueprint, and regression manifest in one candidate-scoped change.
6. Rewrite the three retained rollout-shaped owners around their permanent current contracts and real freshness inputs; migrate exact negative cases for the five completed construction models.
7. Remove the five authorized construction models from current manifest, semantic mesh, blueprint, BCL evidence, and intent authority after replacement evidence is green.
8. Upgrade the existing DPF strategy selector to derive valid order and bounded finite-candidate cost, then use it to freeze the remaining functional, contraction, self-audit, derived-document, install, validation, and publication sequence.
9. Complete the coordinated per-model path-quality change and consume its current compact results for every continuing or materially changed self model.
10. Replace BCL implementation/test source rows with exact current normative contract sources, compile and live-check that external-promise inventory under its existing owner, then run the compact self-blueprint and Architecture Reduction audit; repair every stale, dangling, duplicate, or unjustified current path.
11. Archive the OpenSpec changes, rebuild intent/model authority after the path move, then run one foreground full validation on the frozen source identity.
12. Synchronize formal author source, safe author shadow, local consumer installation, package metadata, Git/tag, and GitHub release.

Rollback is commit-level before public release. During an individual candidate mutation, failure leaves the candidate unauthorized and the prior current owner remains; no compatibility layer is created. After publication, restoration would be a new explicit product requirement and version, not a hidden fallback.
