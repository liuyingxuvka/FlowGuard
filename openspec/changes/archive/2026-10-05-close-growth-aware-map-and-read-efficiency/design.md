## Context

See proposal.md for motivation. The accepted baseline has 54 model owners and 63 active intent lineages. Real affected-owner reuse works, but the three normal functional tasks do not transport growth observations. A private PRE/POST raw equality gate also rejects the authentic model-pointer CAS. Existing responsibilities, goals, native receipts, typed snapshot identities and protected failures remain the basis of this change.

## Goals / Non-Goals

**Goals:** normal current-or-diagnostic task understanding; finite growth provenance; exact action detail; bounded compact output; invocation-local byte/typed-state reuse; selected native material; stable final integration and independent delivery proof.

**Non-Goals:** arbitrary token/time stopping budgets, whole-repository watchers, rebuilding all 54 software models, universal architecture prescriptions, cross-call unchecked caches, compatibility readers and a new per-test reuse authority.

## Decisions

### Separate verified closure from an authentic diagnostic

A successful task retains independent canonical maturation verification. An insufficient task publishes the original request/report references in receipt-free `flowguard.functional_task_diagnostic.v1`, with `needs_evidence`, the original terminal reason and a four-field first gap. The diagnostic cannot create a Verified result or second success route. Tampered, foreign and stale identities are rejected independently during public read.

### Observe only explicit finite path changes

The request carries exact kind/path/previous_path declarations. The normal producer persists the original request, observes present/missing/unavailable paths, and writes `flowguard.functional_growth_observation.v1` with its raw reference. Empty or absent change declarations retain NOT_OBSERVED. Rename observes the old/new union. Only successful native material authenticates inventory scope; a stale material may supply declared diagnostic context but cannot close a gap. Public read consumes the original observation and performs one independent end guard; it never observes or refreshes software itself.

### Preserve complete canonical authority while narrowing ordinary evidence reads

One SelectedReadContext shares original bytes and complete validated typed authority state, keyed by head/snapshot and validation options. A selected native index authenticates the complete parent table, then returns only owner_id/receipt_id/receipt_fingerprint for necessary leaves. The existing finite leaf validator still verifies current Source, proof, contract, environment and native mapping. Global/full validation remains complete. End guards perform fresh reads.

### Make architecture understanding precise and bounded

Typed action targets retain current path/symbol/Source/CodeContract/surface/owner/obligation identity. The compact result distinguishes proven current state, required goals, gaps, compromises and unknown scope, with original detail refs. Empty candidates cannot prove optimal architecture. Batch transport prepares lanes once while retaining exact UTF8+LF page-size enforcement and lossless reassembly.

### Extend only the two existing normative subjects

The model_maturation_loop/context-indexed source gains normal-task-context. The authoritative_model_system/task-aware source gains finite-growth-observation and pointer-detail-navigation. Preserve the original three goals and all 63 lineages. Only these two contributions may single-supersede with the exact authenticated union in target_invariant_ids, target_obligation_ids, target_output_ids and declared_consumer_ids; the other 61 protected subjects remain exact. Native preparation and postaccept consume the same extension verifier. Actual source fences, CodeContracts and consumer calls authorize the delta; planning strings do not.

### Authenticate pointer absence without inventing a pointer

The six fixed current profiles comprise the original three plus normal producer, finite growth and pointer availability. The first five require functional closure. The sixth proves authentic zero-pointer availability as not_applicable with task_closed=false and null producer/context/receipt refs. A location request without a real pointer remains needs_evidence. Nonempty pointer positive/negative checks use a separately owned finite fixture with genuine accepted detail, never a fabricated current Source pointer.

### Freeze expensive owners after inexpensive interface checks

Preserve immutable old tools and receipts. Six unnumbered private runtime modules consume a strict receipt-free qualification bootstrap before real qualification; only a successful actual summary permits the final execution request. Cheap CLI/schema/PRE-POST gates precede stable qualification. Source/tool/impact/archive/index identities settle before one final full owner. Formal published identity then supplies local installation; installation and GitHub are separate claims.

## Risks / Trade-offs

- Cached state accidentally hiding validation options: exact option key, root/head/snapshot admission and fresh end guard.
- Diagnostic appearing successful: receipt-free schema and independent original-report replay; never close a deficient task.
- Finite growth appearing global: explicit declared scope and NOT_OBSERVED elsewhere.
- Pointer absence appearing location success: declared applicability mode and separate task-closed/conformance predicates.
- New goals rejected by immutable old target equality: exact two-subject delta shared by preparation/postaccept, with all old targets retained.
- Parallel edits invalidating evidence: explicit file claims, closed shared-file handoffs and validation only after frozen input identity.

## Direct replacement and delivery

Use the current schemas directly without a legacy reader or alias. Finalize and archive this implementation change before the final Source freeze. Runtime receipts, progress and private execution inputs remain output evidence, never self-invalidating Source authority. Final full, publication and local installation remain explicit external completion obligations.
