## Why

FlowGuard already exposes a target-neutral blueprint shape, but its current success aggregation can still report a complete project or self blueprint while model-test alignment is blocked, and several provider, hierarchy, semantic, test, resource, intent, and cleanup claims can be generated from the same declaration that they are supposed to verify. That false-green boundary prevents the blueprint from serving as a trustworthy, naturally growing software or workflow "DNA".

## What Changes

- Make the canonical target-system compiler consume exact frozen provider results, registry identity, target snapshot, inventories, bindings, and evidence instead of allowing a provider to certify its own currentness in the same success step.
- Make project and self success the conjunction of the complete ordered blueprint layers and every required native report; preserve lower-layer success while exposing the first gap and the complete gap set.
- Keep static manifest consistency as one compiler-owned internal child report with an exact claim boundary; remove its public constructor and generic success wording so it cannot impersonate whole readiness.
- Keep the core target-neutral: software-language adapters, non-code workflow adapters, test runners, intent sources, and resource discoverers contribute typed provider evidence without placing Python fields or target-product roles in the kernel.
- Require an independently discovered behavior-bearing denominator, explicit supporting-surface ownership, block-local source-independent semantics, and real parent/child input-output-schema reattachment.
- Bind every required behavior through model obligation, semantic rule, external contract, implementation surface, concrete case, oracle, exact test/native member, and owner-specific execution receipt. Static test design and current execution remain separate.
- Preserve ordinary affected-only and compact use without materializing the whole blueprint. Whole qualification and deterministic export remain explicit actions.
- Make FlowGuard self-qualification an ordinary consumer of the public target-system compiler and add independent external software, non-Python provider, and non-code workflow acceptance fixtures.
- Make self-cleanup consume an independently derived complete candidate denominator and contract only candidates with current equivalence or facade-delegation proof; similarity, size, or same-origin review cannot authorize deletion.
- Update the existing FlowGuard kernel and affected satellite prompts to teach the exact lightweight/deep route, truthful readiness boundary, provider gaps, per-owner evidence, and cleanup handoffs without adding another DNA skill, alias, fallback, or compatibility reader.
- Complete OpenSpec, observed-model authority, SkillGuard source/consumer projection, local package and skill installations, one frozen final gate, and an immutable patch release as separate evidence domains.

## Capabilities

### New Capabilities

None. This change deepens the existing canonical blueprint and maintenance capabilities rather than adding a second blueprint or DNA package.

### Modified Capabilities

- `target-system-blueprint`: Require externally frozen provider identity, target-neutral provider payloads, truthful report aggregation, independent denominators, and real hierarchy reattachment.
- `authoritative-model-system`: Bind whole-blueprint depth and portable export to the sole observed authority without a second empirical product claim.
- `flowguard-api-registry`: Expose one canonical layered-understanding result and retire alternate empirical qualification inputs.
- `flowguard-bounded-system-composition`: Treat build/runtime/configuration/data/service/verification inputs as canonical project resources rather than a separate branch.
- `flowguard-validation-command-surface`: Retire the raw-manifest blueprint authority and require canonical target/project assembly before explicit deterministic project export, with model readiness reported separately from materialization success.
- `software-blueprint-readiness`: Make ordered-layer readiness, independent semantics/oracles/resources/intent, affected projection, and project success mechanically gap-complete.
- `model-test-alignment`: Require exact per-behavior checker design, test/native member identity, owner-specific execution evidence, and no aggregate-receipt substitution.
- `test-evidence-mesh`: Preserve exact leaf ownership, terminal dispositions, receipt freshness, and parent/child composition without relabeling one receipt across owners.
- `hierarchical-model-mesh`: Require parent-child input/output/schema/refinement agreement, cycle/loop closure, affected-sibling review, and current reattachment evidence.
- `model-revision-set`: Reject unknown fallback owners and require exact current receipts for every affected model owner in one atomic revision.
- `architecture-reduction`: Require an independent cleanup denominator, non-circular proof, external-consumer parity, and explicit retain/contract/unresolved disposition.
- `flowguard-self-maintenance-mesh`: Make self-qualification use only the public generic compiler and keep self evidence from licensing external targets.
- `flowguard-ai-entry-simplification`: Return compact affected understanding, deepest proven layer, first gap, and complete status without full blueprint materialization.
- `development-process-flow`: Sequence affected validation, peer-write invalidation, source/install/model/OpenSpec closure, one frozen final gate, and patch publication.
- `flowguard-skill-kernel`: Route ordinary affected work and explicit whole qualification through the existing canonical owners without adding a second mode or global target-role catalog.
- `flowguard-skill-suite-distribution`: Recompile and project the affected source skills as clean standalone consumers and verify installed parity separately from source checks.

## Impact

- Core target/project/self blueprint compilation, provider qualification, implementation/test/resource/intent inventories, topology, model revision, readiness, compact projection, and CLI surfaces.
- FlowGuard self models, external target fixtures, red-team regressions, architecture-reduction evidence, and release validation ownership.
- Affected source skills and their SkillGuard contracts, consumer projections, installed skills, editable/local package, shadow workspace, OpenSpec main specs, version metadata, changelog, Git tag, and GitHub Release.
- No new runtime dependency, language-specific kernel, target-role catalog, compatibility path, or automatic run-all fallback.
