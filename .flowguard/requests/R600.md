# 第十一轮交接包：先读我

这个包是一份**方案**，不是补丁。清单里写的是要做什么、改哪里、怎么验收；代码由你（执行的 AI）来写。唯一的例外是 `60_README草稿/` 里的五个 README 草稿：核对、贴上真实输出以后就可以提交。

主人不在循环里。这个包里没有任何事情要问主人；遇到清单没写到的情况，按本文件和 `附录/PKG11.md` 的规矩自己判断，并记进工作日志。

## 3. 规矩（每张清单都适用）

- **一次一张清单。** 顺序见第 5 节。一张清单的第一个提交，必须在上一张清单的发布标签之后。
- **只在 `main` 上工作。** 发布提交只包含版本文件和 `CHANGELOG.md`，CI 必须是绿的。
- **FlowGuard 只从 git 标签安装**：`git+https://github.com/liuyingxuvka/FlowGuard.git@<tag>`。PyPI 上叫 flowguard 的包是别人的。依赖写 `>=`。
- **说明 H：** 字数、行数、秒数、个数都不是及格线。等待时限、探索预算是旋钮；成本目标只报告。
- **不存判定结果。** 只有能省时间、而且永远不可能把“失败”变成“通过”的东西才允许存。
- **三种能力**（结构、反例、已知坏）一直都要在。
- **主人不在循环里。** 第 2 阶段和第 3 阶段开工之前，把每个仓库对应的清单原文用 `req add <file> --id R<包编号>` 存下来（设计 0.6）。计划里要引主人原话的地方，只引这份；除此之外什么都不许靠引文接受或退役。Guard 自己代码上的发现，一律改代码修掉。
- **工作日志**放在所有仓库之外，最后交给主人（`附录/PKG11.md` 3.8）。
- **不做长文本试验。**
- 完整的约定在 `附录/PKG11.md`：第 3 节和第 5 节有约束力，第 5 节优先。

## 4. 测试会话和隐藏材料（试点闸的每一行）

- 凡是由 AI 来跑的闸行（G4、G5、G10、G14、G15、G16），每个会话都必须满足：
  - 是一个**单独启动的命令行进程**，不能是你的子会话；
  - 用干净的主目录，只放行它需要的命令；
  - **不转任何主人的话**；
  - 发给它的全部文字（提示词、需求、回答）都记进日志。

  原因：上一轮规划时，有 45 个测试会话因为是子会话，收到了主人的聊天原文，结果被污染（`90_审计报告.md` 第 2 节）。
- 运行目录只放 `70_验收材料/` 里的东西和试点的说明文字（`pilot/SKILL.md`、`pilot/rules.md`，闸期间一字不改，日志里记下它们的摘要）。`71_` 只在评分时、在会话结束以后使用。
- G16：每个需求一个新会话；会话结束后，把这个需求的原文从它的收件箱里删掉；三组分别是“什么都不留”“Markdown 笔记”“FlowGuard 试点”。
- 防过拟合：见 `附录/PKG11.md` 3.6。G9a 用的外部应用必须在跑之前选好、记下（名字、提交、为什么合格），跑完不许换。

## 6. 卡住了怎么办；换新会话怎么接着干

- 真卡住时（清单写的命令、消息或文件在代码里对不上）：按设计说明和清单的意图做最小的改动，写进这张清单的 4.2 节和工作日志，然后继续。不问主人。
- 换新会话时：先读工作日志的最后一段，再跑 `check_round_history.py --status`（XR-601 以后才有），然后从它指出的那一条接着做。

## 7. 最后交什么

- 每张清单的发布标签；
- 试点闸逐行的结果，包括 G16 每个阶段的数字；
- 走了三条路里的哪一条；
- 每个 XR-600 / XR-650 改写了哪些条目、为什么。
