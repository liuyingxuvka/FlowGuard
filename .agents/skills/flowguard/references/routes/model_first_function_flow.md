# Route fragment: `model_first_function_flow`

## Trigger

Use the kernel when the task needs provider-neutral behavior/state modeling,
an unclear or cross-route workflow, or a model/evidence gate that no clear
public satellite owns. Clear satellite work stays with that satellite.

## Required input

Freeze evidenced `TaskFacts` and `TaskCoverageDemand`, the accepted current
intent and owner denominator, exact bindings, affected members, claim
boundary, execution profile, modeling mode, and current model/source/check
identities. Preserve unknown, contradictory, unmapped, and scoped facts.

## Owner and scope

The owner is `model_first_function_flow` with role `kernel`. Build the smallest
faithful `Input x State -> Set(Output x State)` model for the admitted boundary.
Keep protected failures, state/effects, completion evidence, known-bad paths,
resources, oracles, and implementation/test joins in their native planes.

## Output and gates

Return the route decision, owner dispositions
(`satisfied|not_triggered|unresolved|blocked`), model boundary, current
path-quality result, counterexamples, evidence, failures, skipped checks,
residual risk, claim boundary, and typed next actions. Code work also needs
DevelopmentProcessFlow admission. A whole-target or release claim requires
an explicit frozen layer plan, provider results, reverse closure, and exact
parent/child/native evidence; static or normative material cannot substitute
for executed evidence.
