# FlowGuard

## Purpose
Select the smallest faithful owner/model; deepen only for exact evidence.

## Entrypoint Scope
Route id and native owner: `model_first_function_flow`; role: `kernel`. Decide `use_flowguard`, `skip_with_reason`, or `needs_human_review` through `behavior_flow`, `argument_flow`, or `decision_flow`.

## Local Material Routing
- Before route selection, read only `references/route_index.md`.
- After the kernel route is selected, read `references/modeling_protocol.md`; it routes the smallest needed part of `references/modeling_core_protocol.md` and `references/modeling_evidence_protocol.md`.
- When kernel maintenance or adoption is in scope, read `references/skill_kernel_protocol.md`, `references/adoption_protocol.md`, `references/framework_upgrade_protocol.md`, or `references/long_check_protocol.md` only for the named boundary.

## Entrypoint Acceptance Map
- Use a clear peer satellite directly; keep zero/multiple candidates visible.
- Keep the kernel for ordinary, unclear, cross-route, portable, maturation, risk, or closure work. Broad claims and addressable gaps end in native closure or an explicit bounded terminal.

## Use When
- Use when behavior/state/order/retry/effects/progress need `Input x State -> Set(Output x State)` and no satellite clearly owns the task.

## Do Not Use When
- Do not force the kernel before a clear satellite, use it for trivial copy/format/direct-command work, or treat check-engine helpers as independently triggerable Codex skills.

## Required Workflow
1. Freeze provenance-bound `TaskFacts` and independent `TaskCoverageDemand`; preserve unknown, contradictory, unmapped, and scoped facts. Ordinary work loads exact affected ids and ancestors; whole inventory/export/qualification needs explicit scope.
2. In an existing modeled target, use only the accepted revision's complete `CurrentEffectiveIntentView`, independent current model-owner denominator, and exact owner bindings. The revision delta is history, never a current-intent substitute.
3. Resolve every demanded owner as `satisfied|not_triggered|unresolved|blocked`; `ordinary|standard|deep|release` changes work depth, not correctness.
4. Build the smallest faithful `Input x State -> Set(Output x State)` model with protected failures, state/effects, completion evidence, and known-bad paths. Every new or materially changed model receives one current lightweight path-quality review inside ModelMaturation; unchanged rows reuse only exact current evidence.
5. Escalate one affected model to finite deep path review only for an exact current trigger. Preserve hard semantics before comparing named multi-dimensional costs, keep `observed` and `normative_target` separate, and return a bounded conclusion without a default scalar or global-optimum claim.
6. Run declared checks and mature counterexamples to current evidence or an explicit external/scoped/stalled/bounded terminal. Independently verify the receipt; reject self-rated understanding and caller-authored authority.
7. Code work separately requires DevelopmentProcessFlow admission: `ready|ready_scoped|no_code_requested|blocked|stale`. User choice bounds an attempt but cannot upgrade understanding. `risk_evidence_ledger` alone decides confidence; closure checks identity and terminal integrity without rescoring.
8. Explicit whole-target scope uses the provider-neutral core/evidence contract, frozen profile/provider artifacts, and native layer owners. Non-code workflows use their real actors, states, transitions, resources, and verification without fabricated software or Python layers.

## Hard Gates
- Model-purpose gate: freeze task-specific failure(s) and the claim boundary; bind the exact candidate to native good/bad-per-failure/oracle/current evidence. Reusable types are not fixed-purpose: no mode/fallback; only FlowGuard-declared checks may support completion claims.
- Require the real FlowGuard check engine and AGENTS.md managed record; never create a fake mini-framework or expose check-engine helpers as independently triggerable Codex skills.
- Only the observed snapshot and accepted `ModelRevisionSet` are current. Never promote history, non-pass evidence, a normative target, parent result, or installation.
- Path-quality evidence is one compact current ModelMaturation result plus a detail fingerprint; it adds no public route, CLI, compatibility reader, second pointer, or ordinary reconstruction step. Reimplementation or translation is separate explicit target work, not path-quality proof.
- Target roles and transitions stay in the target model. Paths/symbols prove traceability, not semantics; language is a provider detail. Static design, leaf execution, resources, and oracles retain distinct identities.
- Triggered portable, UI/payload, replacement, lifecycle, WorkContext, diagram,
  and release rules remain mandatory in selected references. Template search,
  no-match review, and template harvest closure are mandatory only inside the
  single `risk_template_library` route after an explicit reuse/publication
  request or current executable evidence of a bounded stable pattern intended
  for use outside the target project; ordinary modeling, repair, maintenance,
  and release do not inherit that gate.
- Self-qualification uses the public target path and proves only that fixture; generic confidence also needs independent external and non-code fixtures.

## Output Requirements
- Return evidence, failures, blockers, skipped checks, residual risk, claim boundary, typed next actions, route/reference, model/counterexamples, path-quality summary, sufficiency, admission, user choice, and validation. Blueprint output adds target/profile, affected members, layer statuses/depth/gaps, behavior closure, and resource/intent status.
