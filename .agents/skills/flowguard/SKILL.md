# FlowGuard

## Purpose
Select the smallest owner; deepen for a trigger or native gap. Claim strength sets evidence depth; lightweight use remains.

## Entrypoint Scope
Route id and native owner: `model_first_function_flow`; role: `kernel`. Decide `use_flowguard`, `skip_with_reason`, or `needs_human_review` through `behavior_flow`, `argument_flow`, or `decision_flow`.

## Local Material Routing
- Before route selection, read only `references/route_index.md`.
- After the kernel route is selected, read `references/modeling_protocol.md`; it routes the smallest needed part of `references/modeling_core_protocol.md` and `references/modeling_evidence_protocol.md`.
- When kernel maintenance or adoption is in scope, read `references/skill_kernel_protocol.md`, `references/adoption_protocol.md`, `references/framework_upgrade_protocol.md`, or `references/long_check_protocol.md` only for the named boundary.

## Entrypoint Acceptance Map
- Use a clear peer satellite directly when exactly one current owner matches; zero or multiple candidates stay visible.
- Keep the kernel for ordinary modeling, unclear/cross-route work, portable composition, risk, maturation, and closure.
- On a broad-claim, prediction, Model Miss, ambiguity, high-impact, or addressable-gap trigger, load the mapped reference and continue to native closure or an explicit external/scoped/stalled/bounded terminal.

## Use When
- Use when behavior/state/order/retry/effects/progress need `Input x State -> Set(Output x State)` and no satellite clearly owns the task.

## Do Not Use When
- Do not force the kernel before a clear satellite, use it for trivial copy/format/direct-command work, or treat check-engine helpers as independently triggerable Codex skills.

## Required Workflow
1. Freeze provenance-bound `TaskFacts` from the request, observed model, public surfaces, and lifecycle/process change. Preserve unknown, contradictory, unmapped, and scoped facts; compile independent `TaskCoverageDemand`. Callers may add facts or narrow claims, never erase observations. Add implementation-inventory/binding owners only for explicit whole-target blueprint, export, or qualification scope.
2. Resolve every demanded owner exactly once as `satisfied|not_triggered|unresolved|blocked`; TaskCoverage and maturation share its identity. `ordinary|standard|deep|release` describes work depth, not weaker correctness.
3. Build the smallest faithful executable model for triggered owners, including protected failures, state, side effects, completion evidence, and representative known-bad paths.
4. Run declared checks and mature counterexamples until each demand has current evidence or an explicit external/scoped/stalled/bounded terminal. Independently verify one receipt binding task, demand, candidate, inputs, obligations, result, evidence, and gaps. Reject self-rated understanding or caller-authored current/digest/receipt fields.
5. For code work, preserve maturation and obtain separate DevelopmentProcessFlow admission: `ready`, `ready_scoped`, `no_code_requested`, `blocked`, or `stale`. Permission cannot upgrade understanding.
6. `risk_evidence_ledger` alone decides full/scoped/blocked confidence. Closure checks exact identity, material presence, and terminal integrity without rescoring risk. Preserve failed, skipped, stale, scoped, and not-run evidence.
7. Summaries use the read-only understanding projection and separate sufficiency, implementation admission, and user execution choice. It never runs/resumes owners, writes evidence, or grants admission.
8. Explicit target-system scope is provider-neutral: software, workflows, services, agents, pipelines, and mixed targets use exact observation/authority providers. Consume canonical behavior blocks, exact code/semantic/oracle/test bindings, resource and intent inventories, affected-only projection, and static readiness.

## Hard Gates
- Model-purpose gate: pre-build/change freeze task-specific failure(s)/boundary; bind the candidate to native good/bad-per-failure/oracle/current evidence. Reusable types are not fixed-purpose: no mode/fallback; only FlowGuard-declared checks may support completion claims.
- Require the real FlowGuard check engine and AGENTS.md managed record; never create a fake mini-framework.
- Existing-model currentness comes only from the sole observed snapshot. Targets and experiments remain separate until one accepted whole `ModelRevisionSet` updates authority.
- Do not weaken invariants, invent alternate success paths, or use missing/stale/skipped/`not_run`/progress-only evidence for broad confidence.
- Target-product people, roles, permissions, and transitions belong inside the target software model. FlowGuard supplies modeling and evidence owners; it does not invent a global catalog of application roles.
- When triggered, portable composition, UI/payload proof, replacement, evidence lifecycle, WorkContext, diagram semantics, release freshness, and template harvest closure remain mandatory; details live in selected references.
- Paths/symbols are traceability, not behavior semantics. Static closure needs block-local rules, portable bindings, owner-declared good/boundary/bad cases, one accepted checker design per case and behavior dimension, evidenced helper ownership, current oracles, and separate execution evidence. A generated case or checker id cannot close the design. Each resource category retains one canonical owner/artifact/fingerprint/purpose/lifecycle/semantics reference; a reduced checklist is not authority. Language is a provider detail, not the target-system gate.

## Output Requirements
- Return evidence, failures, blockers, skipped checks, risk, residual risk, claim boundary, typed next actions, route/reference choice, model snapshot, counterexamples, sufficiency, admission, user choice, and validation. When triggered, also return behavior closure, readiness depth/first gap, and resource/intent status.
