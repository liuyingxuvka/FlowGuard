# FlowGuard Model Miss Review

## Purpose
Apply root-cause backpropagation from a post-green failure into its commitment, model boundary, owner contract, same-class cases, tests, and claim.

## Entrypoint Scope
This standalone FlowGuard satellite skill owns `model_miss_review` (`public_owner`) and grounded miss classification/closure, not feature invention.

## Local Material Routing
After positive admission, read `references/model_miss_protocol.md` for miss types, backpropagation, evidence, reattachment, and closure.

## Entrypoint Acceptance Map
Accept concrete failure evidence plus prior claim state; classify/generalize the miss; block point-fix-only or stale closure; hand follow-up work to typed owners.

## Use When
- Use after a FlowGuard-green runtime, test, replay, log, manual, or UI failure, or when a repair needs `boundary_missing` and bug-class evidence.

## Do Not Use When
- Do not patch only one instance, invent a feature commitment, or proceed without concrete failure evidence; return unclear modeling to `flowguard`.

## Required Workflow
1. Run existing-model preflight; identify the failed `behavior_plane`, commitment, primary owner, error signature, and miss type.
2. Search that plane first. Reuse its commitment/owner; create a coverage gap only when no promise matches, and keep other planes as typed context.
3. Backpropagate root cause. When asked, derive a deterministic deletion-minimal conflict and positive witness from the owner report; preserve its decision and keep the projection read-only.
4. Add a contract-exhaustion same-class case/family seed and bind relevant fields or old paths.
5. Add observed and same-class owner code contract evidence; rerun alignment, mesh, freshness, and risk gates; close or scope the class.

## Hard Gates
- Model-purpose gate: pre-build/change freeze task-specific failure(s)/boundary; bind candidate to native good/bad-per-failure/oracle/current evidence. Reusable types are not fixed-purpose: no mode/fallback; only FlowGuard-declared checks may support completion claims.
- Require the real FlowGuard check engine and AGENTS.md managed record; forbid fake mini-frameworks.
- A later green command or point regression cannot close the class; require target-aware replay and owner-code binding when applicable.
- Unknown field/old-path disposition, stale reattachment, open family scan, or missing template-harvest closure blocks broad confidence.
- Shared symptom text across product, AI-operation, and process planes does not merge recurrence families without an explicit relation and separate local owners.
- Diagnostic conflict and positive witness need per-item necessity witnesses. Say deletion-/subset-minimal, never global-minimum or unique. Missing positive non-vacuity blocks the projection; it never overrides the review or closes the miss.

## Output Requirements
- Return evidence, failures, blockers, skipped_checks, residual_risk, claim_boundary, typed_next_actions, a miss-repair diagram, generalized-case status, and any subordinate diagnostic with the preserved owner decision.
